# Hashing

임의의 크기를 가진 데이터를 고정된 데이터의 크기로 변환 시키는 것  
예시 : 문자열 -> 어떤 정수 값(int, long long)  

이를 이용한 테이블이 Hashing Table이다  
(해싱을 거쳐 나온 값과 관련된 위치에 해당 데이터를 저장)  
[해싱 테이블과 관련 내용](https://hsp1116.tistory.com/35)  

## 문자열 해싱  
긴 문자열을 일정한 수식에 의한 정수로 변환하는 것  
보통 문자열에 대한 해싱은 다음과 같은 **롤링 해시** 처리함(처리 용이성)  
여기서, p와 M은 특정 양수값임.  (**polynomial rolling hash function**, or  Rabin fingerprint )

$$ HashValue = \displaystyle\sum_{i=0}^{n-1} f(s_i)  p^i \ mod \ M$$ 

혹은

$$ HashValue = \displaystyle\sum_{i=0}^{n-1} f(s_i)  p^{n-1-i} \ mod \ M$$  

p는 보통 문자열에 입력할 수 있는 문자의 개수와 비슷한 정도 가 좋음  
보통 M은 소수로 두는 경우가 많음  
함수는 보통  
-  아스키 코드 값
-  소문자 알파벳만 나오는 경우 f(문자) = 문자 - 'a' 
-  소, 대문자 알파벳만 나오는경우, 각각 경우를 나눠서 각 문자열에 대한 값은 결국 이어지게 연산. 
    -  Ex : 소문자 알파벳 : 0~25, 대문자 : 26 ~ 51   
-  $i$ 번째 소수

등등 있으나, 절대적인것은 아니고, 문제상황에 따라 특수하게 적용해야 할 수 도 있음   

등등이 있음  
## 문자열 해싱 이점  
1. M 값의 크기가 클수록, Hash Collision이 일어날 확률이 적어짐  
(동일한 해시값이지만 문자열은 서로 다른 경우)

2. 문자열 해싱을 통해 Hash Collision이 없을 경우, 문자열 비교 시간 복잡도는 O(1) 이 된다.  
(총 시간 복답도 : 기존 -> $O(nm)$ , 해싱처리 : $O(n + m)$)

3. 해시 값이 서로 다를 경우 <span style="color:red;">해당 두 문자열은  다름</span>  
-> 이는 Rabin-Karp 알고리즘의 근원이 되기도 함 

3번 증명  :  
두 문자열이 같으면 해시 값은 같다   
(대우) -> 해시 값이 다르면, 두 문자열은 다르다.

## 주의점
Hash Collision 때문에 문자열이 다른 데도 해시값이 같은 경우가 존재 함  
따라서 가능한 이 충돌이 안 일어나도록 하는 것이 매우 중요 함  

보통 여기서 이중 해시 (해시충돌 시 다른 해시함수를 한 번 더 적용한 결과를 이용) 인 경우가 많다.  

혹은 좋은 해시 함수를 찾는 것도 하나의 방법이 됨 (parameter 값 설정 등등)


# Rabin - Karp 
해시 기법을 이용한 문자열 매칭 알고리즘  


주로 계산 방식 ( Rabin fingerprint )

$$ HashValue = \displaystyle\sum_{i=0}^{n-1} f(s_i)  p^i \ mod \ M$$ 

혹은

$$ HashValue = \displaystyle\sum_{i=0}^{n-1} f(s_i)  p^{n-1-i} \ mod \ M$$  

여기서 $p = 2$, $f(s_i) = AsciiCode$ 로 두는 경우가 많음. 

## 동작순서
탐색 대상 문자열 길이를 $m$, 패턴 문자열 길이를 $n$으로 가정 ($m <= n$)  

1. 탐색 대상 문자열의 처음부터 패턴 문자열의 길이만큼 문자열을 잘라 해시 값을 계산  
2. 패턴 문자열의 해시 값을 계산.  
3. 만약 같은 경우  
    -> 해당 구간에서 문자열 1:1 비교  

    만약 해시값이 다른 겅우, 혹은 해시값이 같아도 문자열이 다른 경우  
    -> 탐색 대상 문자열에서 한 칸씩 이동하여 다시 해시 값을 계산  (즉 한칸 이동 후 2번으로 다시 돌아감)

4. 이 과정중 3번에서 동일한 문자열이라고 판단되는 경우 매칭확인, 아닌 경우는 없다고 판단  


### 한칸 이동하면서 해싱값 구하기(3)
핵심 포인트는 한칸 이동시 다시 해싱값 구하는 것이 아닌, 
딱 추가, 제거 되는 부분만 처리하고 나머지 부분은 p를 곱하는 방식  

긴 문자열 해시값 = $p$ * (긴 문자열 해시값 - 가장 앞에 있는 문자의 수치값) + 새롭게 들어온 문자의 수치값

## 주의점  
- mod 연산을 사용할 필요는 없다 하지만 안정적으로 하기 위해선 mod 연산을 강력히 권장함  

- overflow 주의  

## 시간복잡도  
평균적으로 $O(n + m)$ 이 걸림  

단 Hash collision을 고려한 문자열 패턴 매칭까지 고려 할 경우  최악인 경우 $O(nm)$ 이 될 수 있음  

(kmp는 어떠한 경우든 $O(n+m)$ 이 보장됨  )

## 예시문제  
1786 찾기 문제 에서 KMP 대신 라빈-카프 방식도 가능함  
```c++
#include <iostream>
#include <vector>
#include <string>
 
using namespace std;
typedef long long ll;
 
ll a = 302;
ll p = 1e9+7;
ll powa[1000010];
 
int main() {
    string T,P; getline(cin, T); getline(cin, P);
    
    int lenT = T.size();
    int lenP = P.size();
    if(lenT < lenP) {
        cout << 0 << '\n';
        return 0;
    }
    
    
    // a의 제곱값을 미리 구해놓음
    powa[0] = 1;
    for(int i=1; i<P.size(); i++) {
        powa[i] = powa[i-1] * a %p;
    }
    
    // 각각 P길이만큼 해시값 구함
    ll hashT = 0;
    ll hashP = 0;
    
    for(int i=0; i<P.size(); i++) {
        hashT = (hashT + T[i] * powa[P.size()-1-i]) %p;
        hashP = (hashP + P[i] * powa[P.size()-1-i]) %p;
    }
    
    vector<int> rs;
    if(hashT == hashP) rs.push_back(1);
    
    for(int i=1; i<=(T.size()-P.size()); i++) {
        // 앞글자 빼고, a만큼 곱해서 한자리씩 올리고, 새로 한글자 추가
        hashT = (hashT - T[i-1] * powa[P.size()-1])%p;
        // 음수인경우 확인
        if(hashT < 0) hashT += p;
        hashT = hashT * a % p;
        hashT = (hashT + T[i+P.size()-1] ) % p;
        if(hashT == hashP) rs.push_back(i+1);
        
    }
    
    cout << rs.size() << '\n';
    for(int x : rs) cout << x << '\n';
    
    return 0;
}

```
